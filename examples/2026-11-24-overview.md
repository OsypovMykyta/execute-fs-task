# Overview Page Implementation Plan

> **For agentic workers:** execute this plan with `/execute-fs-task`. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** The overview page keeps the period control and shows totals plus three charts for the signed-in user's transactions in the selected period.

**Architecture:** The server exposes one aggregation endpoint scoped to the authenticated user. The client fetches it whenever the period changes and renders totals and charts from the response.

**Tech stack:** NestJS + Prisma (server), React + TanStack Query + Recharts (client).

> This is an example. Replace the paths, stack and commands with your own.

---

## API contract

Both sides must follow this contract exactly.

```http
GET /api/overview?from=2026-11-01&to=2026-11-30
Authorization: Bearer <token>
```

```ts
type OverviewResponse = {
  totals: { income: number; expense: number; balance: number }; // in cents
  byCategory: { categoryId: string; name: string; amount: number }[]; // expenses only
  byDay: { date: string; income: number; expense: number }[]; // ISO date, every day in range
};
```

- `from` and `to` are required ISO dates; `from > to` returns `400`.
- Only transactions of the signed-in user are counted.

## Global constraints

- Do not change existing transaction endpoints.
- Do not edit `app.module.ts` except to register `OverviewModule`.
- Amounts stay in cents end to end; format only in the UI.
